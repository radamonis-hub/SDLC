# Выбор веб-приложения как способа взаимодействия с системой

## Контекст и постановка задачи

CaterFlow предназначена для клиентов и сотрудников кейтеринговой компании «ФуршетПро». Клиенты должны иметь возможность просматривать каталог блюд, формировать меню и отправлять заявки, а сотрудники — управлять заказами и информацией каталога.

Пользователи могут обращаться к системе с различных устройств. Необходимо выбрать способ взаимодействия, который обеспечит удобный доступ к функциональности без сложной установки и настройки программного обеспечения на устройствах пользователей.

Какой тип приложения следует использовать для реализации CaterFlow?

## Драйверы решения

* Доступность системы для клиентов и сотрудников с различных устройств.
* Отсутствие необходимости устанавливать отдельное приложение на устройство пользователя.
* Простота обновления и сопровождения программного обеспечения.
* Поддержка пользовательских и административных функций.
* Соответствие требованиям адаптивности интерфейса (REQ-PORT-001).
* Возможность централизованного развёртывания и обслуживания приложения (REQ-INST-001).

## Рассмотренные варианты

* Разработка отдельного настольного приложения.
* Разработка веб-приложения с доступом через браузер.
* Разработка отдельных мобильных и настольных приложений.

## Итог решения

Выбранный вариант: «Веб-приложение с доступом через браузер».

Данный вариант позволяет клиентам и сотрудникам использовать систему без установки дополнительного программного обеспечения. Обновление приложения выполняется централизованно на сервере, поэтому пользователям не требуется самостоятельно устанавливать новые версии.

Веб-приложение соответствует характеру задач CaterFlow и позволяет предоставить единый интерфейс для работы с каталогом, меню, заявками и административными функциями.

Решение имеет предварительный статус и подлежит согласованию с заказчиком.

### Последствия

* Хорошо, потому что доступ к системе осуществляется через стандартный веб-браузер.
* Хорошо, потому что не требуется устанавливать отдельное приложение на устройства пользователей.
* Хорошо, потому что обновление выполняется централизованно.
* Хорошо, потому что единое приложение может предоставлять интерфейсы для клиентов и сотрудников с разными уровнями доступа.
* Нейтрально, потому что для работы требуется сетевое подключение к серверу.
* Плохо, потому что корректное отображение интерфейса необходимо проверять в различных браузерах и на разных размерах экранов.
* Плохо, потому что доступность системы зависит от работоспособности серверной инфраструктуры.

### Подтверждение

Соблюдение решения проверяется в ходе функционального и пользовательского тестирования.

Необходимо убедиться, что:

* Основные функции системы доступны через веб-браузер.
* Клиенты и сотрудники могут использовать приложение в соответствии со своими ролями.
* Интерфейс корректно отображается на настольных компьютерах, планшетах и мобильных устройствах.
* Обновление приложения не требует переустановки программного обеспечения на устройствах пользователей.
* Основные страницы и операции соответствуют установленным требованиям производительности.

## Плюсы и минусы вариантов

### Отдельное настольное приложение

* Хорошо, потому что позволяет использовать возможности операционной системы и локальные ресурсы устройства.
* Хорошо, потому что может обеспечивать работу с некоторыми функциями без постоянного подключения к сети.
* Плохо, потому что требует установки на устройства пользователей.
* Плохо, потому что обновление приложения необходимо выполнять на каждом устройстве.
* Плохо, потому что доступ клиентов с мобильных устройств потребует дополнительной разработки.

### Веб-приложение с доступом через браузер

* Хорошо, потому что не требует установки дополнительного программного обеспечения.
* Хорошо, потому что доступно с различных устройств при наличии браузера и подключения к сети.
* Хорошо, потому что обновление приложения выполняется централизованно.
* Хорошо, потому что позволяет использовать единый интерфейс для клиентов и сотрудников.
* Нейтрально, потому что работа зависит от доступности сервера и сетевого подключения.
* Плохо, потому что необходимо учитывать совместимость с различными браузерами и размерами экранов.

### Отдельные мобильные и настольные приложения

* Хорошо, потому что интерфейс можно адаптировать под особенности каждой платформы.
* Хорошо, потому что можно использовать специфические возможности мобильных и настольных устройств.
* Плохо, потому что потребуется разработка и сопровождение нескольких приложений.
* Плохо, потому что увеличивается объём работ по тестированию и обновлению.
* Плохо, потому что такой подход увеличивает затраты времени и не соответствует ограниченному сроку разработки проекта.
