# CaterFlow

**CaterFlow** — веб-система для автоматизации оформления заказов на услуги кейтеринга компании «ФуршетПро».

## 1. О проекте

Система предназначена для упрощения взаимодействия клиентов с кейтеринговой компанией. Она позволяет просматривать каталог блюд и готовых наборов, формировать индивидуальное меню, рассчитывать предварительную стоимость заказа и доставки, а также отправлять заявки на оформление заказа.

CaterFlow разрабатывается с учётом потребностей клиентов и сотрудников компании, участвующих в обработке заказов.

## 2. Основные возможности

- Просмотр каталога блюд и готовых наборов.
- Формирование индивидуального меню.
- Расчёт предварительной стоимости заказа.
- Расчёт стоимости доставки.
- Регистрация и авторизация клиентов.
- Оформление и отправка заявок.
- Управление каталогом и заказами.
- Обработка поступивших заявок менеджерами.
- Формирование PDF-документов с информацией о заказе.

## 3. Пользователи системы

| Роль | Основные возможности |
|---|---|
| Гость | Просмотр каталога и доступной информации |
| Зарегистрированный клиент | Формирование меню и оформление заявок |
| Менеджер | Обработка заявок и управление заказами |
| Администратор | Управление системой и основными данными |

## 4. Архитектура и технологии

Для разработки CaterFlow выбрана архитектура **модульного монолита**. Она предполагает разделение системы на логические модули при сохранении единого развёртываемого приложения.

Используемые технологические решения:

| Компонент | Технология |
|---|---|
| Серверная часть | C++ |
| Веб-фреймворк | Drogon |
| Система управления базами данных | PostgreSQL |
| Тип приложения | Веб-приложение |
| Архитектура | Модульный монолит |

Обоснование выбора архитектуры и технологий представлено в документах ADR.

## 7. Планирование разработки

В каталоге `docs/plans/` находятся документы, отражающие процесс оценки и планирования разработки:

- `estimates.md` — оценка трудоёмкости разработки;
- `initial-plan.md` — первоначальный план реализации;
- `modified-plan.md` — изменённый план с учётом новых требований;
- `agreed-plan.md` — согласованный с заказчиком план.

## 8. Согласованный план

Разработка системы запланирована на три итерации общей продолжительностью 12 недель.
